## 문서 범위

이 문서는 Billit의 인증, 데이터 표현, HTTP 응답과 페이지 규격을 정리한다. [백엔드 API 공통 규칙](https://github.com/JECT-Study/Trip-Sheet-5th-Server/blob/develop/docs/contributing/api-conventions.md)이 기준이며, 도메인별 요청과 응답 제안, 정책상 미결 사항은 각 도메인 문서에서 관리한다.

## 공통 규격

| 항목 | 기준 |
| --- | --- |
| 기본 경로 | `/api/v1` |
| 인증 | 회원 API는 `Authorization: Bearer {accessToken}`. 가입 전 API는 `Authorization: Bearer {registrationToken}`으로 사용자 확인. 인증 없는 공개 API는 개별 명세에 정의 |
| JSON | camelCase, enum은 대문자 SNAKE_CASE |
| ID | 문자열. `memberId`는 회원 계정, `tripMemberId`는 여행별 참여자, `tripId`는 여행 ID |
| 날짜와 시각 | 날짜 `YYYY-MM-DD`, 시각 ISO 8601 UTC |
| 금액과 환율 표현 | 소수점 이하 2자리 문자열과 통화 코드. 저장 단위와 계산 규칙은 아래 충돌 해결 필요 |
| 성공 본문 | JSON 객체의 `data` 필드에 결과를 담고, 페이지 응답은 최상위 `page`를 추가 |
| 실패 본문 | `{ "code": "도메인_사유", "message": "안내 문구", "errors": null }`, 필드 오류는 `errors` 목록 |
| 생성 | `201`, 식별 가능한 리소스는 `Location` 제공 |
| 본문 없는 성공 | `204`, 응답 본문 없음 |
| 목록 | 페이지가 필요하면 offset 방식. `page=0`, `size=20`, 최대 100, 허용 정렬 기준과 값이 같은 경우의 순서 명시 |
| 파일 | 업로드는 multipart, 실제 형식과 용량 검증. 비공개 파일 접근 권한 검증 |
| PATCH | 생략은 유지. null 제거 허용 필드는 개별 명세에서 지정 |

조회는 `200`, 입력 오류는 `400`, 인증 오류는 `401`, 권한 오류는 `403`, 없는 대상은 `404`, 현재 상태와의 충돌은 `409`를 기본으로 검토한다. 삭제되거나 접근 차단된 대상을 어떻게 안내할지는 도메인별 확정이 필요하다. 개별 오류 코드와 메시지는 아직 확정하지 않았다.

## 인증과 권한

가입을 완료한 회원은 Billit 서버가 발급한 Access Token을 `Authorization: Bearer {accessToken}` 헤더로 보낸다. 소셜 로그인에 사용하는 제공자의 ID 토큰과 Apple 인가 코드, 로그인 유지에 사용하는 Refresh Token, 수정과 정산에 사용하는 잠금 토큰은 용도가 다르다.

| 이름 | 의미 | 사용하는 요청 |
| --- | --- | --- |
| Apple 인가 코드 | Apple SDK에서 받은 일회용 코드. 서버는 Apple 연결 해제에 필요한 토큰을 확보하기 위해 교환한다. | Apple 소셜 로그인 요청의 `authorizationCode` |
| 소셜 제공자의 ID 토큰 | Google, Apple, Kakao가 발급한 토큰. 서버는 서명, 발급자, 발급 대상과 만료 등을 검증한다. | 앱이 소셜 로그인 요청의 `idToken`으로 전달한다. |
| 가입 전용 토큰 | 소셜 인증을 마친 가입 미완료 사용자를 확인하는 토큰. 일반 회원 권한은 없음 | 가입 정보 조회와 가입 완료, 닉네임 중복 확인의 인증 수단 |
| Billit Access Token | Billit API를 요청하는 회원을 확인하는 토큰 | 로그인 후 API의 Authorization 헤더 |
| Billit Refresh Token | Access Token을 새로 발급받을 때 사용하는 토큰. 갱신 성공 시 새 토큰으로 회전하고 사용한 기존 토큰은 폐기 | Access Token 갱신 요청의 JSON Body. 유효 기간은 [인증 만료 정책](../policy/authentication.md#인증-만료)을 따른다. |
| 잠금 토큰 | 특정 지출 수정 또는 정산 준비 작업을 구분하는 값 | 같은 작업의 저장, 연장과 취소 요청. Access Token과 별도로 확인 |
| 지출 저장 고유키 | 응답을 받지 못해 같은 저장을 재요청할 때 중복 생성을 막는 값 | 지출 생성 요청. 잠금 토큰과 별도로 사용 |

각 API의 인증 조건은 요청할 수 있는 사용자를 뜻한다. 여행 관리자는 해당 여행을 만든 회원이며 서비스 운영자를 뜻하지 않는다. 지출 수정은 기록자 또는 여행 관리자에게만 허용한다. 실제 결제자와 지출 기록자는 다를 수 있다.

소셜 인증을 마친 가입 미완료 사용자에게 가입 전용 토큰을 발급한다. 가입 정보 조회, 닉네임 중복 확인과 가입 완료 API는 이 토큰으로 본인을 확인하며, 일반 회원용 Access Token과 Refresh Token은 가입 완료 후 발급한다. 가입 전용 토큰으로 일반 회원 API를 호출하거나 회원용 토큰을 갱신할 수 없다. 가입 완료 응답 유실 시에는 같은 가입 요청을 재시도해 회원용 토큰을 받을 수 있다. 처리 흐름과 구현 선택은 [가입 전용 토큰 설계](../design/registration-token.md)를 따른다.

> 논의 필요
>
> 가입 전용 토큰의 형식, 가입 완료 후 복구 요청의 식별과 허용 기간, 회원용 토큰 재전달 또는 재발급 방식을 결정한다. 전달 위치는 [가입 API](user.md#가입-api)를, 30분의 유효 기간은 [회원 식별 정책](../policy/authentication.md#회원-식별)을 따른다.

- 로그인한 회원인지 확인한 뒤 각 여행과 요청 대상에 대한 권한을 검사한다. 클라이언트가 보낸 역할과 기록자 ID를 그대로 신뢰하지 않는다.
- 비로그인 참여자, 나간 회원, 탈퇴 회원과 빈자리를 구분한다. memberId가 null이라는 이유만으로 모두 같은 상태로 처리하지 않는다.
- 결제자, 부담자, 송금인과 수령인은 여행 참여자 ID인 tripMemberId로 구분한다. 이름이 같아도 다른 참여자다.
- 조회 응답이 수정이나 취소 가능 상태를 보여줘도 변경 요청 시점에 다시 확인한다.
- 잠금 토큰은 해당 작업을 시작한 사람에게만 제공한다. 토큰이 같아도 회원 인증과 요청 권한 검사를 생략하지 않는다.

## 스펙 확정 전에 결정할 사항

| 안건 | 충돌 또는 미결 | 영향 |
| --- | --- | --- |
| 계산 주체와 순서 | 공통 규칙은 서버 계산과 환산 순서를 정했지만 최신 지출 설계는 POC 후 결정으로 남겼다. | 계산 API, 생성과 수정 요청, 결과 검증 |
| 금액 단위 | API의 소수 2자리 문자열과 DDL의 통화 최소 단위 BIGINT 사이 변환, 원화 소수 보존이 미결이다. | 모든 금액 필드와 합계 검증 |
| 최대 금액 | 금액과 환율의 상한, 품목 수와 요청 크기 상한이 미결이다. | DTO 검증과 오류 |
| 잠금 | 토큰 전달 위치, 잠금 유지 시간, 연장, 앱이 잠금 토큰을 잃어버렸거나 서버 응답을 받지 못했을 때의 처리 방식이 미결이다. | 수정과 정산의 재시도 |
| 멱등성 | 지출 생성 키 도입은 확정, 범위와 보존 기간, 다른 내용과 다시 요청했을 때의 응답 규칙은 미결이다. | 생성 중복과 통신 재시도 |
| 상태 변경 재시도 | 여행 확정, 정산 발행과 취소, 수령 확인의 재요청 성공 또는 충돌 응답을 정해야 한다. | FE 재시도 정책 |
| 개인정보 | 탈퇴 후 보존과 숨김, OCR 외부 전달, 이미지 삭제 기준이 미결이다. | 조회 응답과 삭제 처리 |
| 목록 조회 | 각 목록의 페이지 적용 여부, 필터 enum, 정렬 필드와 범위 경계를 정해야 한다. | 목록과 전체 선택 |

## 성공 응답

### SuccessResponse

| 필드 | 타입 | nullable | 포함 조건 | 설명 |
| --- | --- | --- | --- | --- |
| `data` | API별 정의 | API별 정의 | JSON 성공 응답 | 단일 객체 또는 배열. 개별 API에서 구체적인 모델을 정의 |
| `page` | Page | 아니요 | 페이지네이션을 적용한 응답만 | 최상위에 배치 |

HTTP `204 No Content`는 JSON 본문을 반환하지 않는다. 생성 성공은 HTTP `201 Created`와 `Location`, 조회와 수정의 데이터 반환은 HTTP `200 OK`를 기본으로 한다. 비동기 접수를 채택하면 `202 Accepted`와 상태 조회 방법을 함께 정의한다.

다음은 성공 응답이 data를 감싸는 형식을 보여주는 예시다. 실제 data의 필드는 각 API에 정의한다.

```json
{
  "data": {
    "memberId": "member-example-a"
  }
}
```

### Page

| 필드 | 타입 | nullable | 포함 조건 | 설명 |
| --- | --- | --- | --- | --- |
| `page` | Integer | 아니요 | 항상 | 현재 페이지 번호, 0부터 시작 |
| `size` | Integer | 아니요 | 항상 | 요청 페이지 크기, 기본 20, 1~100 |
| `totalElements` | Integer | 아니요 | 항상 | 전체 필터와 일치하는 건수 |
| `hasNext` | Boolean | 아니요 | 항상 | 다음 페이지 존재 여부 |

첫 요청은 `page=0`이며 생략해도 동일하다. 다음 요청은 현재 페이지에 1을 더한다. 마지막 페이지를 넘으면 HTTP `200 OK`와 `data: []`를 반환하며 전체 건수는 유지한다. 음수 페이지, 범위 밖 size와 지원하지 않는 sort는 `400`이다. 필터는 기본 AND이며 생략하면 해당 조건을 적용하지 않는다. 정렬은 `필드,방향`으로 전달하며 마지막 기준에 ID를 포함한다. 허용 필드와 기본 정렬은 개별 API에서 확정한다.

빈 결과의 예시:

```json
{
  "data": [],
  "page": {
    "page": 0,
    "size": 20,
    "totalElements": 0,
    "hasNext": false
  }
}
```

## 오류 응답

### ErrorResponse

| 필드 | 타입 | nullable | 포함 조건 | 설명 |
| --- | --- | --- | --- | --- |
| `code` | String | 아니요 | 항상 | FE가 분기할 공통 또는 도메인 오류 코드 |
| `message` | String | 아니요 | 항상 | 사용자에게 표시 가능한 안내 |
| `errors` | Array&lt;FieldError&gt; | 예 | 항상 | 필드 검증 오류가 없거나 특정할 수 없으면 null |

### FieldError

| 필드 | 타입 | nullable | 포함 조건 | 설명 |
| --- | --- | --- | --- | --- |
| `field` | String | 아니요 | 항상 | 요청 필드명 |
| `reason` | String | 아니요 | 항상 | 사용자에게 표시 가능한 검증 실패 사유 |

필드 오류는 field 이름순으로 정렬한다. 예시는 백엔드 공통 규칙에 정의된 입력 오류를 사용한다.

```json
{
  "code": "COMMON_INVALID_REQUEST",
  "message": "요청이 올바르지 않습니다.",
  "errors": [
    {
      "field": "amount",
      "reason": "0보다 커야 합니다."
    }
  ]
}
```

내부 예외, SQL과 민감정보를 응답에 포함하지 않는다. 도메인별 오류 표는 개별 API에서 발생할 수 있는 조건만 작성하며 오류 코드 사전은 해당 문서 마지막에 둔다.

## 데이터와 예시의 해석

- 요청 표의 필수 여부는 필드를 보내야 하는지를 뜻한다. 별도로 허용한다고 적지 않은 요청 필드는 null을 보낼 수 없다. 응답의 nullable은 필드 값이 null일 수 있는지를 뜻하며 필드 생략 여부와는 다르다.
- Enum은 명시된 대문자 값을 사용한다. 알 수 없는 값과 enum에 숫자를 보낸 요청은 `400`으로 거절하며 기본값으로 치환하지 않는다.
- 날짜는 `YYYY-MM-DD`, 시각은 ISO 8601 UTC로 전달한다. 결제와 환전 날짜는 사용자가 입력한 현지 날짜를 그대로 저장하며 UTC 변환하지 않는다. 결제와 환전의 시각, 시간대, 현재 위치와 국가코드는 수집하지 않는다. API 환율 조회는 입력한 현지 결제 날짜를 기준으로 요청한다. FE 표시 시간대와 상태 판정 시간대는 구분하며, 기간 경계와 업무 시간대가 미결이면 API 바로 아래 표시한다.
- 예시 ID와 URL, 토큰은 설명용이다. 실제 개인정보, 운영 토큰과 내부 주소를 포함하지 않는다.
- 같은 모델을 사용하는 API는 모델을 링크한다. 일부 구조만 정의할 수 있는 경우 일부 필드만 정의한 모델임을 표시하고 완전한 요청 예시는 보류한다.
- 원본 통화 값은 통화와 함께 표시한다. 잔액은 음수를 허용하지만 송금액은 양수이며 금액의 상한과 계산 단위는 도메인 결정이 필요하다.
