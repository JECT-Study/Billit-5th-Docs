## 로그인

### 로그인 수단

화면: `AUTH-02`

서비스는 Google, Apple, Kakao 소셜 로그인을 제공한다.
서비스는 이메일과 비밀번호를 쓰는 자체 가입과 로그인을 제공하지 않는다.

서버는 소셜 인증 결과로 회원을 식별한다.
제공자별 인증 정보와 검증 계약은 [인증 API 스펙](../api-spec/authentication.md#auth-01-소셜-로그인)을 따른다.
Apple 연결 해제 조건은 [회원 탈퇴 정책](user.md#계정과-개인정보)을 따른다.

앱은 현재 기기에서 마지막으로 로그인한 소셜 수단을 표시한다.

### 회원 식별

화면: `AUTH-02`, `AUTH-03`

기존 회원이 가입할 때 쓴 소셜 계정으로 인증하면 서비스는 기존 회원 계정으로 로그인한다.
서비스는 서로 다른 소셜 계정을 별도 회원으로 취급하며, 여행과 정산 기록을 자동으로 합치지 않는다.

가입 절차를 완료하지 않은 사용자는 30분간 유효한 가입 전용 토큰으로 가입 절차를 진행한다.
가입 전용 토큰이 만료되면 사용자는 소셜 인증을 다시 해야 한다.
서비스는 가입을 완료한 뒤에 일반 회원용 토큰을 발급한다.
가입 조건과 닉네임 초기값은 [유저 정책서의 회원가입](user.md#회원가입)을 따른다.

#### 적용 예시

다음은 회원 식별의 가상 예시다.

```text
1. 기존 회원이 가입할 때 사용한 Kakao 계정으로 로그인한다.
   결과: 기존 회원 계정으로 로그인한다.

2. Kakao로 가입한 회원이 Google 계정으로 처음 인증한다.
   결과: 별도 회원의 가입 절차를 진행하며 기존 여행과 정산 기록을 합치지 않는다.
```

### 인증 실패와 취소

화면: `AUTH-02`

소셜 인증에 실패하거나 사용자가 인증을 취소하면 서비스는 로그인과 가입을 완료하지 않는다.
사용자는 로그인 화면에서 다시 시도할 수 있다.
사용자가 소셜 로그인을 취소하면 앱은 별도 안내 없이 로그인 화면으로 돌아간다.

### 로그인 후 진입

화면: `AUTH-02`, `HOME-01`

기존 회원이 로그인하면 앱은 여행 목록으로 이동한다.
신규 회원의 가입 완료 후 진입과 초대 코드 안내는 [유저 정책서의 가입 완료 후 진입](user.md#가입-완료-후-진입)을 따른다.

## 인증 유지

### 앱 재실행

화면: `AUTH-01`, `AUTH-02`

인증 상태가 유효하면 앱을 종료하고 다시 실행해도 앱은 로그인을 유지한다.
로그인을 유지하면 앱은 온보딩과 로그인 화면을 거치지 않고 여행 목록으로 이동한다.
서비스는 앱 종료를 로그아웃으로 처리하지 않는다.

### 인증 만료

화면: `AUTH-02`

Access Token은 발급 후 15분간 유효하다.
Refresh Token은 발급 후 30일간 유효하다.
토큰 갱신에 성공하면 서비스는 기존 Refresh Token을 폐기하고, 새 Refresh Token에 30일의 유효 기간을 부여한다.
Refresh Token이 만료되거나 유효하지 않으면 앱은 다시 로그인하도록 안내한다.

갱신 응답을 받지 못하면 앱은 같은 Refresh Token으로 한 번만 다시 요청한다.
마지막 갱신 후 30초 안에 직전 Refresh Token으로 들어온 첫 재요청을 서비스는 응답을 받지 못한 재시도로 보고 새 토큰을 한 번 더 발급한다.
이 조건을 벗어나 갱신에 이미 쓴 Refresh Token이 제출되면 서비스는 재사용으로 보고 그 로그인 세션의 토큰을 즉시 무효화한다.
재사용을 감지해도 서비스는 다른 로그인 세션을 유지한다.
재요청에서도 응답을 받지 못하면 앱은 네트워크 오류로 처리한다.

## 로그아웃

### 적용 범위

화면: `SET-01`

로그인한 회원은 설정에서 로그아웃을 요청할 수 있다.
회원이 로그아웃을 확인하면 앱은 현재 기기의 인증을 해제하고 로그인 화면으로 이동한다.

현재 기기에서 로그아웃해도 서비스는 다른 기기의 로그인 상태를 유지한다.
로그아웃한 기기에서 인증이 필요한 기능을 쓰려면 회원은 다시 로그인해야 한다.

로그아웃을 처리하면 서비스는 그 로그인 세션의 Access Token과 Refresh Token을 즉시 무효화한다.
Access Token이 만료되었으면 회원은 새 토큰을 발급받지 않고 유효한 Refresh Token으로 로그아웃할 수 있다.
이미 종료된 세션으로 다시 로그아웃을 요청하면 앱은 그 세션의 로컬 토큰을 정리한다.

서비스는 토큰 갱신과 로그아웃을 현재 기기의 로그인 세션 기준으로 처리한다.
요청과 응답 규격은 [인증 API 스펙](../api-spec/authentication.md)을 따른다.

#### 적용 예시

다음은 기기별 로그아웃의 가상 예시다.

```text
1. 휴대폰과 태블릿에 로그인한 회원이 휴대폰에서 로그아웃한다.
   결과: 휴대폰은 로그인 화면으로 이동하고 태블릿은 로그인 상태를 유지한다.
```

### 기록 유지

화면: `SET-01`

회원이 로그아웃해도 서비스는 회원 계정, 참여 중인 여행방, 지출과 정산 기록을 유지한다.
회원 탈퇴로 계정 접근을 차단하는 기준은 [유저 정책서의 회원 탈퇴](user.md#회원-탈퇴)를 따른다.
