## 등록과 권한

화면: `TRIP-04`, `EXP-05`

여행 시작 후 관리자와 로그인 참여자는 지출을 등록할 수 있다. 비로그인 참여자는 지출을 등록하거나 결제자가 될 수 없으며, 부담자로는 선택할 수 있다.

지출 상세는 저장된 결제 정보와 부담 내역을 제공한다. 정산 이후에도 산출 근거를 조회할 수 있다.

| 행동 | 기록자 | 관리자 | 그 외 로그인 참여자 |
| --- | --- | --- | --- |
| 지출 수정 | 허용 | 허용 | 불가 |
| 지출 삭제 | 허용 | 허용 | 불가 |

수정 중이거나 정산 대상으로 잠긴 지출은 다른 수정과 삭제를 허용하지 않는다.

## 입력과 저장

화면: `EXP-02`, `EXP-03`, `TRIP-05`

분할 방식은 전체 1/N과 메뉴/품목별로 구분하며, 기본값은 전체 1/N이다. 분할 방식을 바꾸면 품목 상세를 제외한 공통 입력값을 유지한다.

지출명, 결제 통화, 결제 날짜, 결제 수단, 적용 환율, 결제자와 금액을 입력한다. 지출명은 필수이며 길이를 제한하지 않는다. 목록에서는 12자를 초과하면 말줄임으로 표시한다.

결제 통화는 여행 기본 통화를, 결제 날짜는 작성일을, 결제자는 작성자를 기본값으로 제공한다. 결제자는 로그인 참여자 중 한 명만 선택한다. 결제 수단은 카드, 현금, 트래블 카드다.

결제 날짜는 사용자가 선택한 결제 당시의 현지 날짜다. 시각은 수집하지 않으며 UTC로 변환하지 않는다. 현재 위치와 국가코드는 수집하지 않는다.

부담 참여자는 기본 선택 없이 직접 선택하며 전체 선택을 제공한다. 부담 참여자가 없으면 계산과 저장을 허용하지 않는다.

입력값 검증을 통과하면 참여자별 최종 부담액을 보여준다. 사용자가 별도로 저장을 확정해야 지출을 기록한다. 같은 저장 요청을 재시도해도 지출을 중복 기록하지 않는다. (회의 결정)

> 논의 필요
>
> 11월 7일 회의에서 명시적 임시 저장은 서버에, 앱의 일시 이탈은 로컬에 저장하고 앱 내 페이지 이탈 시에는 저장하지 않는 방향을 논의했다. 임시 저장 필수값과 MVP 반영 범위, 저장 및 복원 조건은 확정해야 한다.

적용 환율과 기본값은 [환율 정책](exchange-rate.md#지출-환율)을 따른다.

## 분배와 할인

화면: `EXP-02`, `EXP-03`

전체 1/N은 선택한 부담 참여자끼리 나눈다. 품목별 분배는 각 품목에 지정한 참여자끼리 나눈다.

상품 할인액은 해당 품목에, 전체 할인액은 결제 전체에 적용한다. 전체 1/N의 최종 결제액은 할인 전 총 금액에서 전체 할인액을 뺀 금액이다. 품목별 최종 결제액은 할인 전 총 금액에서 상품 할인액 합계와 전체 할인액을 뺀 금액이다. 최종 결제액은 0 미만일 수 없다.

전체 할인액은 개인별 결제 부담 비율에 따라 분배한다. 1차 MVP에서는 계산된 개인 부담액의 수기 수정을 제공하지 않는다. (회의 결정)

품목 합계와 입력 총액이 맞지 않으면 차액을 안내하고 다음 단계 진행을 막는다. 참여자별 최종 부담액 합계는 최종 결제액과 같아야 한다.

> 논의 필요
>
> 비례 할인액의 반올림과 잔여 금액 처리 기준을 확정해야 한다.
>
> 품목 할인 반영 전 합계를 총액과 비교할지, 할인 반영 후 합계에 맞춰 총액 기준을 조정할지 결정한다.
>
> 남은 금액을 전체 부담 참여자에게 배정할지, 별도로 선택한 참여자에게 배정할지 결정한다.

품목 할인과 총액의 비교 기준은 화면정의서의 검증 설명과 최종 결제액 식이 일치하도록 확인해야 한다.

## 환산과 자투리

화면: `EXP-02`, `EXP-03`

지출 분배의 자투리는 소수점 이하 값이 큰 참여자부터 최소 단위씩 배정한다. 참여자 목록의 첫 사람에게 모두 배정하지 않는다.

화면정의서의 환산 금액 반올림 기준은 사사오입, 소수점 둘째 자리다.

> 논의 필요
>
> 소수점 이하 값이 같을 때 적용할 참여자 순서를 정해야 한다.
>
> 지출 저장과 환산 과정에서 자투리를 두 번 배정하는 기존 시나리오를 유지할지, 계산과 저장 순서를 조정할지 결정한다.
>
> 환산과 분배 순서, 반올림 시점, 통화별 최소 단위와 저장 정밀도를 확정해야 한다.
>
> 프론트엔드 계산 결과를 저장 시 검증할지, 서버 계산 결과를 제공할지 소수점 정확성 POC 후 결정한다.

## 수정과 잠금

화면: `EXP-05`

수정 권한을 획득한 사용자만 수정할 수 있다. 다른 사용자가 수정 중이면 진입을 제한한다. 수정 잠금은 획득 후 5분간 유효하고, 만료 전에 한 번 요청할 때마다 2분씩 연장할 수 있다. 수정 확정 전에는 다른 참여자에게 기존 저장 내역을 보여준다.

수정도 입력 검증, 재계산 결과 확인, 수정 완료 순서로 진행한다. 수정 완료 시 부담액 합계를 다시 검증하고 잠금을 해제한다.

정산 대상으로 잠긴 지출은 수정할 수 없다. 확정된 정산에 포함된 지출을 수정하려면 먼저 [정산 취소 조건](settlement.md#정산-취소)을 충족해야 한다.

이전 수정 작업의 지연된 해제 요청이 새 수정 작업의 잠금을 해제하지 않아야 한다. (회의 결정)

> 논의 필요
>
> 연장 상한과 최종 부담액 확인 화면 이탈 시 해제 시점을 정해야 한다. 정산 준비 잠금의 시간은 별도 정책을 따른다.

## 영수증 인식

화면: `EXP-01`

사용자는 지출 입력 화면에서 분할 방식을 고른 뒤 영수증 자동 입력을 요청할 수 있다. 별도의 기록 방법 선택 화면은 제공하지 않는다.

갤러리 선택 또는 촬영으로 한 장을 입력한다. 필요한 사진 또는 카메라 권한을 요청하고, 거부되면 권한 허용 방법을 안내한다.

지출명, 결제 날짜, 통화, 총 금액, 품목과 상품 할인액, 전체 할인액을 인식해 선택한 분할 방식의 입력란에 채운다. 인식 결과는 사용자가 검수하고 수정한 뒤 계산과 저장을 진행한다. 인식만으로 지출을 확정 저장하지 않는다.

### 이미지 처리와 결제 정보

영수증 이미지는 외부 AI인 Gemini API의 유료 티어로 인식한다. 원본 이미지는 인식이 끝나면 바로 삭제하며 서버에 보관하지 않는다. 사용자가 저장한 지출 정보만 남는다. 인식하는 동안 서버가 이미지를 어디에 두고 처리하는지는 [지출 설계](../design/expense.md#영수증-이미지)를 따른다.

인식 전에 이미지의 민감 정보를 가리는 처리는 하지 않는다. 대신 카드번호, 카드 승인번호, 영수증 번호, 카드사와 전화번호는 인식 결과에서 제외해 사용자에게 보여 주지 않으며 저장하지 않는다.

사용자가 영수증 자동 입력을 처음 요청하면 이미지가 어떻게 처리되는지 한 번 안내한다. 안내는 동의를 받는 절차가 아니며, 사용자가 확인하면 영수증 인식을 진행한다. 안내 확인 여부는 기기에 저장하므로 앱을 다시 설치하면 다시 안내한다.

> 논의 필요
>
> 주소, 가맹점 사업자번호와 결제자명도 인식 결과에서 제외할지 확정한다.
>
> 인식에 실패한 경우와 영수증이 아닌 이미지를 구분해 안내할지 결정한다. BE는 구분할 수 있다고 답했다.
>
> 원본 외부 전달의 적절성과 스토어 심사 영향은 별도로 확인한다. PM의 전달 가능 의견을 법률 또는 심사 검증 완료로 취급하지 않는다.
