## 회원가입

### 가입 완료 조건

화면: `AUTH-03`

신규 사용자는 소셜 인증 후 필수 약관 동의, 계정 닉네임 설정과 이름 및 만 나이 입력을 완료해야 회원으로 가입된다. 필수 절차를 완료하지 않으면 일반 회원으로 처리하지 않는다.

개인정보 동의는 필수이며 마케팅 활용 동의는 선택이다. 필수 약관에 모두 동의하지 않으면 가입할 수 없으며, 마케팅 활용 동의 여부는 가입을 막지 않는다.

동의 여부는 사용자가 확인한 약관 버전을 기준으로 기록한다. 동의한 기기의 운영체제(iOS 또는 Android)와 동의 시점의 앱 버전도 함께 기록한다. 앱 버전은 사용자마다 다를 수 있어 어떤 앱에서 동의했는지 확인하는 데 사용한다.

이름과 만 나이는 필수 입력이다. 가입 화면은 소셜 정보에서 가져온 값을 표시하고, 가져오지 못한 항목은 사용자가 직접 입력한다.

> 논의 필요
>
> 필수 약관의 명칭과 전문을 확정해야 한다. 나이 수집에 대한 동의 범위를 확인해야 한다.

### 선택 정보

화면: `AUTH-03`

성별, 여행 총무 여부, 정산 시 번거로운 점은 선택 항목이다. 정산 시 번거로운 점은 최대 2개까지 선택할 수 있으며, 기타를 선택하면 직접 입력할 수 있다. 사용자가 응답하지 않아도 가입을 완료할 수 있다.

가입 화면은 소셜 계정의 표시 이름이 있으면 닉네임 입력란을 그 값으로 채운다. 사용자는 값을 수정할 수 있으며, 가입을 완료할 때 제출한 값에 닉네임 규칙을 적용한다.

### 가입 중단과 재개

화면: `AUTH-02`

가입을 중단한 사용자는 다시 소셜 인증을 한 뒤 미완료 가입 절차를 진행한다. 가입을 중단했다는 이유만으로 가입 완료 회원으로 처리하지 않는다.

### 가입 완료 후 진입

화면: `HOME-01`, `TRIP-01`

가입이 완료되면 로그인 상태로 여행 목록에 진입하며, 신규 가입자에게만 초대 코드 입력 팝업을 자동 제공한다. 기존 회원의 로그인에는 팝업을 자동 제공하지 않는다.

가입 직후 코드 팝업에서도 유효한 코드를 검색한 뒤 결과를 확인하고 참여한다. 여행 참여를 완료하면 해당 여행으로 이동한다. 팝업을 닫으면 여행 목록에 머물며, 참여 중인 여행이 없으면 빈 상태 화면을 제공한다.

여행 검색과 참여 조건은 [여행 정책서의 초대와 참여](trip.md#초대와-참여)를 따른다.

> 논의 필요
>
> 팝업 종료 직후 별도 여행 생성 버튼을 노출할지, 기존 여행 생성 진입점만 제공할지 결정한다.

## 프로필

### 닉네임

화면: `AUTH-03`

닉네임은 계정 단위로 설정하며 모든 여행방에서 동일하게 사용한다. 1차 MVP에서는 가입 후 닉네임을 변경할 수 없다.

서비스 전체에서 이미 사용 중인 닉네임은 등록할 수 없다. 중복 상태에서는 가입을 완료할 수 없다.

닉네임은 1~10자이며 한글 완성형(가~힣), 영문(A~Z, a~z)과 숫자(0~9)만 허용한다. 한글 자모, 공백과 특수문자는 사용할 수 없다. 입력을 멈춘 뒤 0.5초 후 자동으로 중복 여부를 확인한다.

닉네임 중복 확인 후 입력값을 변경하면 확인 상태를 초기화한다. 가입을 완료할 때도 중복 여부를 다시 확인하며, 중복이면 가입을 완료하지 않는다.

> 논의 필요
>
> 닉네임 글자 수 산정 기준을 확정해야 한다.

#### 적용 예시

```text
1. 서로 다른 두 사용자가 같은 닉네임의 중복 확인을 통과한다.
   결과: 먼저 가입을 완료한 사용자만 해당 닉네임을 사용하며 다른 사용자는 새 닉네임을 입력한다.

2. 회원이 여행 A와 여행 B에 참여한다.
   결과: 두 여행에서 같은 계정 닉네임을 사용한다.
```

### 프로필 이미지

화면: `SET-01`

회원은 설정의 프로필 영역에서 갤러리 이미지를 선택해 프로필 이미지를 등록하거나 수정할 수 있다. 설정에는 닉네임과 가입한 소셜 로그인 수단을 표시한다.

> 논의 필요
>
> 선택 이미지 용량을 5MB 이하로 제한할지, 다른 상한을 적용할지 결정한다.
>
> 허용 이미지 형식과 등록 가능한 최종 용량을 확정해야 한다.

## 회원 탈퇴

### 요청과 최종 확인

화면: `SET-01`

로그인한 회원은 설정에서 회원 탈퇴를 요청할 수 있다. 탈퇴 전에 삭제되는 정보, 정산 완료 시 삭제와 탈퇴일로부터 최대 90일 보존 기준, 여행 접근에 미치는 영향을 안내한다. 미완료 정산이 있으면 송금 관계별 총건수를 표시한다.

안내 사항 확인 체크박스에 동의하고 최종 확인 팝업에서 탈퇴 의사를 확인한 경우에만 탈퇴를 처리한다. 최종 확인하지 않으면 탈퇴하지 않는다.

### 계정과 개인정보

화면: `SET-01`

회원이 탈퇴하면 해당 계정의 접근을 차단하고 계정 정보, 프로필과 개인 리시트를 삭제한다. 정산에 필요한 최소 공동 기록의 한시적 보존은 다음 항목을 따른다.

Apple로 가입한 회원이 탈퇴하면 [Apple의 계정 삭제 지침](https://developer.apple.com/documentation/technotes/tn3194-handling-account-deletions-and-revoking-tokens-for-sign-in-with-apple)에 따라 Apple에서 발급한 토큰을 폐기해 빌릿과 Apple 계정의 연결을 해제한다.

> 논의 필요
>
> 삭제와 비식별 처리의 항목별 구분 및 실제 처리 범위를 확정해야 한다.

### 공동 기록과 미완료 정산

화면: `SET-01`, `SETTLE-04`

미완료 정산이 있어도 회원 탈퇴를 허용한다. 여행 및 정산 진행 상태와 관계없이 언제든지 탈퇴할 수 있다.

공동 기록에서는 기존 닉네임 대신 ‘탈퇴한 사용자’로 표시한다. 같은 여행방에 탈퇴자가 여러 명이면 ‘탈퇴한 사용자 1’, ‘탈퇴한 사용자 2’로 구분하며 각자의 송금 관계를 합치지 않는다. 결제 내역에는 탈퇴자 표시 이름과 금액만 제공하고 결제 상세 품목과 개인 리시트는 다른 참여자에게 노출하지 않는다.

진행 중인 정산에 필요한 기존 송금 관계와 금액은 유지한다. 탈퇴자가 수령인이면 미확인 관계를 ‘수령 확인 불가’로 표시하되 탈퇴 전에 완료된 수령 확인은 유지한다. 송금인이 탈퇴했어도 기존 수령인은 ‘받았어요’를 사용할 수 있다. 송금인과 수령인이 모두 탈퇴한 관계는 다른 참여자에게 숨기고 내부 기록만 일시 보존한다.

정산 완료 시 탈퇴자의 송금 관계와 금액을 즉시 삭제한다. 미정산이 지속되어도 탈퇴일로부터 최대 90일이 지나면 관련 정산 기록을 삭제한다. 탈퇴자가 여러 명이면 각자의 탈퇴일을 기준으로 보존 기간을 적용한다.

기록 삭제 후 해당 항목을 숨기고 ‘일부 정산 내역이 삭제되었어요’라고 안내한다. 1차 MVP에서는 일부 기록이 삭제되면 총 송금액도 숨긴다. 다른 참여자의 정산과 수령 확인은 계속할 수 있다.

> 논의 필요
>
> 5차 화면정의서 SET-01에 나온 완료 후 최소 결과 30일 보존은 대상 데이터와 적용 여부를 확인해야 한다. 진행 중 정산의 송금 관계와 금액은 현행 정책대로 완료 시 삭제한다.
>
> 「회원 탈퇴 원문」의 90일은 서비스 자체 정책안이다. 분리 보존의 적법한 근거와 범위, 완료 즉시 삭제 및 최대 90일 보존 기준은 법률 검토가 필요하며 법률상 허용된 기간으로 확정된 것은 아니다.

> 추후 검토
>
> 일부 기록 삭제 후 남은 내역만 합산해 총 송금액을 표시한다.

### 여행 생성자 탈퇴

화면: `SET-01`, `MY-01`

여행 생성자와 관리자는 같은 권한 주체이며, 생성자도 회원 탈퇴할 수 있다. 생성자가 탈퇴하면 해당 생성자가 만든 여행방은 다른 참여자도 접근할 수 없다.

1차 MVP에서는 다른 참여자에게 관리자 권한을 양도하거나 자동 이전하지 않는다. 생성자에게는 다른 참여자 전원의 여행방 접근이 차단되고 미완료 정산이 남을 수 있음을 안내한 뒤 최종 탈퇴 의사를 확인한다.

생성자가 탈퇴하면 기존 여행방 기록을 삭제하되 진행 중인 정산에 필요한 최소 기록은 보존한다. 다른 참여자는 ‘내 공간 → 내 정산 내역’에서 본인의 정산서를 확인하고 ‘받았어요’를 사용할 수 있다. 기존 여행명과 필요한 송금 관계 및 금액을 유지하며, 탈퇴자 기록은 위 보존 및 삭제 기준을 따른다.

여행방에서 나가기와 회원 탈퇴는 구분한다. 여행방 단위의 나가기는 [여행 정책서의 여행 나가기](trip.md#여행-나가기)를 따른다.

## 재가입

화면: `SET-01`, `AUTH-02`

탈퇴자는 동일한 소셜 계정으로 재가입할 수 있다. 재가입자는 탈퇴 전과 구별되는 신규 회원으로 처리하며, 기존 여행방, 지출과 정산 기록을 자동 복원하거나 연결하지 않는다.

> 논의 필요
>
> 탈퇴 직후 재가입을 허용할지, 일정 기간 제한할지 결정한다.
>
> 탈퇴 전 닉네임을 재사용할 수 있게 할지, 일정 기간 사용을 제한할지 결정한다.
