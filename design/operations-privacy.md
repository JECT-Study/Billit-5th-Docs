# 운영 환경과 개인정보 보호

개인정보 처리방침과 유출 대응 매뉴얼에서 개발팀에 확인을 요청한 항목 중, 서버와 인증에 관한 내용을 실제 설정 기준으로 정리한다. 처리방침 문구는 이 문서에서 확정한 사실만 옮겨 쓴다.

마지막 확인: 2026-11-16, 운영·개발 서버 설정과 서버 저장소 구현 기준.

## 클라우드와 저장 위치

서버와 파일 저장소는 모두 Oracle Cloud Infrastructure(OCI) 춘천 리전(`ap-chuncheon-1`)에 있다. 서울 리전이 아니다.

| 데이터 | 저장 위치 | 보관 |
| --- | --- | --- |
| 회원, 여행, 지출, 로그인 세션 | 운영 데이터 서버의 PostgreSQL | 탈퇴 정책에 따른다 |
| 운영 DB 백업 | OCI Object Storage 비공개 버킷 | 7일 ([백업](#백업)) |
| 서버 로그 | 개발·모니터링 서버의 Loki | 7일 ([서버 로그](#서버-로그)) |
| 서버 지표(CPU, 메모리 등) | 개발·모니터링 서버의 Prometheus | 14일 |
| 영수증 원본 이미지 | 저장하지 않는다 ([영수증 이미지](#영수증-이미지)) | 없음 |

운영 데이터 서버는 공인 IP가 없는 사설 서브넷에 있다. PostgreSQL(5432)과 Redis(6379)는 운영 앱 서버에서 오는 연결만 허용한다.

> 논의 필요
>
> 클라우드 사업자 보안 사고 지원 연락처는 OCI 고객 지원 경로를 확인해 추가한다.

## 소셜 로그인으로 저장하는 항목

| 항목 | 저장 | 비고 |
| --- | --- | --- |
| 소셜 제공자와 제공자 내부 계정 ID(`sub`) | 저장 | 같은 계정 식별용 |
| 소셜 표시 이름(Google `name`, Kakao `nickname`, Apple `fullName`) | 저장 | 닉네임 초기값으로 쓰지 않는다 |
| 이메일 | 저장하지 않음 | ID 토큰에 있어도 읽지 않는다 |
| 프로필 사진 | 저장하지 않음 | 소셜 제공값을 쓰지 않는다 |
| 출생연도, 나이 | 저장하지 않음 | 가입 때 만 18세 이상 여부만 확인하고 그 값도 저장하지 않는다 |
| Apple Refresh Token | 암호화해 저장 | AES-256-GCM. 탈퇴 때 Apple 연결 해제에 쓴다 |

이메일을 저장하지 않으므로 유출 사고 때 이메일로 개별 통지할 수 없다.

> 논의 필요
>
> - 소셜 표시 이름은 쓰는 곳이 없어졌다. 저장을 중단할지 [USER-01](../api-spec/user.md#user-01-가입-정보-조회)에서 정한다. 중단하면 위 표에서 뺀다.

## Apple 연결 해제

Apple 로그인 회원이 탈퇴하면 저장한 Apple Refresh Token으로 Apple 토큰 해지 API(`/auth/revoke`)를 호출한다. 해지 호출은 [서버 PR #33](https://github.com/JECT-Study/Billit-5th-Server/pull/33)에 구현했고, 탈퇴 API를 구현할 때 연결한다. 해지가 성공한 경우에만 저장한 토큰을 지운다. 해지 실패와 복호화 불가의 처리는 [인증 세션과 토큰](authentication.md#apple-연결-해제-토큰)을 따른다.

## 탈퇴 때 삭제와 보존

탈퇴 처리는 탈퇴 API를 구현할 때 다음 기준으로 만든다. 업무 기준은 [유저 정책](../policy/user.md#회원-탈퇴)을 따른다.

| 대상 | 처리 |
| --- | --- |
| 소셜 식별값, 계정 닉네임, 선택 정보 | 탈퇴 즉시 지운다 |
| 여행방 닉네임(`trip_member.guest_name`) | 탈퇴 즉시 지운다. 공동 기록에는 참여자 상태 `WITHDRAWN`을 보고 '탈퇴한 사용자 N'으로 표시한다 |
| 회원 행 | 지우지 않고 탈퇴 상태로 바꾼다 |
| Apple 토큰 | Apple 로그인 회원이면 탈퇴 즉시 해지한다([Apple 연결 해제](#apple-연결-해제)) |
| 송금 관계와 금액 | 계정과 연결을 끊은 별도 기록으로 남긴다 |
| 탈퇴 사유 | 회원 ID 없이 `withdrawal_reason` 테이블에 따로 저장한다 |

별도 기록은 정산이 완료되었거나 탈퇴일로부터 90일이 지나면 서버 스케줄러가 매일 지운다. 90일은 회사 정책안이며 법적 근거는 [유저 정책](../policy/user.md#공동-기록과-미완료-정산)의 논의 필요를 따른다.

로그인 참여자의 여행방 닉네임도 `guest_name`에 저장한다([ERD 변경 목록](erd-changes.md#반영할-변경)). 탈퇴할 때는 값을 다른 문구로 바꾸지 않고 비운다. `UNIQUE (trip_id, guest_name)`은 NULL끼리 중복으로 보지 않으므로 같은 여행방에서 여러 명이 탈퇴해도 충돌하지 않는다.

유저 정책은 프로필 이미지와 개인 리시트도 탈퇴 즉시 삭제한다고 정한다. 두 항목은 지금 따로 저장하지 않아 위 표에 넣지 않았다.

- 프로필 이미지는 저장 컬럼과 스토리지 경로가 아직 없다. 저장 방식을 정할 때 탈퇴 즉시 Object Storage에서 지우는 처리를 함께 정하고 위 표에 추가한다.
- 개인 리시트는 따로 저장하지 않고 정산과 송금 데이터로 조회할 때마다 만든다. 계정과 연결을 끊으면 탈퇴자 본인은 볼 수 없고, 다른 참여자에게는 [공동 기록 표시 기준](../policy/user.md#공동-기록과-미완료-정산)에 따라 노출하지 않는다. 리시트를 이미지 등으로 저장하게 되면 위 표에 추가한다.

## 서버 로그

서버는 웹 서버 접근 로그와 애플리케이션 로그를 남긴다.

| 로그 | 남기는 항목 | 남기지 않는 항목 |
| --- | --- | --- |
| 웹 서버 접근 로그 | 요청 시각, 호스트, 메서드, 경로(쿼리 제외), 응답 코드, 응답 크기, 처리 시간, 요청 ID, User-Agent | IP 주소, 쿼리 문자열, 쿠키, `Authorization` 헤더, 요청 본문 |
| 애플리케이션 로그 | 이벤트 이름, 회원 ID, 세션 ID, 오류 종류 | 토큰, 인가 코드, 비밀값 |

로그는 수집 단계에서 토큰과 비밀값 형태의 문자열을 한 번 더 가린 뒤 저장한다. 보관 기간은 7일이며 지난 로그는 자동으로 지운다.

> 논의 필요
>
> 유출 대응 매뉴얼은 접속 기록을 최소 3개월 보관하는지 묻는다. 지금은 7일이고 IP 주소를 남기지 않는다. 접속 기록 보관이 필요하면 다음을 함께 정한다.
>
> - 보관 기간(3개월 이상)과 그만큼의 저장 공간
> - IP 주소를 남길지. 남기면 처리방침의 자동 수집 항목에 추가한다.

## 백업

운영 DB는 매일 04:00(KST)에 전체 백업해 OCI Object Storage 비공개 버킷에 올린다. 7일이 지난 백업은 지우되, 최근 성공한 백업 7개는 남긴다. 매월 1일 백업을 별도 환경에 복원해 복구되는지 시험한다.

탈퇴하거나 삭제한 데이터도 백업에는 최대 7일 남는다. 처리방침의 파기 조항에 이 기간을 적는다.

## 전송 구간 암호화와 접근 권한

- 앱과 서버 사이는 HTTPS(TLS 1.2, 1.3)로 통신한다. 지금은 임시 도메인 인증서를 쓰며, 실제 도메인이 정해지면 바꾼다.
- 서버에 사람이 접속할 때는 사설 네트워크(Tailscale)를 거쳐 SSH 키로만 로그인한다. 비밀번호 로그인은 막혀 있다.
- 배포는 배포 전용 계정이 허용된 배포 명령만 실행할 수 있다.
- DB와 Redis는 서비스 전용 계정과 비밀번호로 접근하며, 비밀번호는 서버의 환경 파일에만 둔다.

## 유출 사고 때 바로 할 수 있는 차단 조치

| 조치 | 효과 |
| --- | --- |
| JWT 서명 키(`JWT_SECRET`) 교체 후 재배포 | 발급한 모든 Access Token, Refresh Token과 가입 전용 토큰이 무효가 된다. 모든 회원이 다시 로그인한다 |
| 로그인 세션 일괄 종료(`auth_session.revoked_at` 일괄 기록) | 서명 키를 바꾸지 않고 기존 세션만 끊는다 |
| DB, Redis, 외부 API 키 교체 | 유출된 비밀값으로 접근하지 못하게 한다 |
| 서버 접속 계정, SSH 키와 Tailscale 기기 제거 | 사람의 서버 접근을 회수한다 |
| 이전 이미지로 롤백 | 배포 도구로 직전 정상 버전으로 되돌린다 |

유출 규모는 DB에서 영향받은 회원 수와 항목을 SQL로 바로 셀 수 있다.

> 논의 필요
>
> - 1차 기술 대응(원인 파악, 접근 차단, 로그 보존)을 맡을 사람과 비상 연락 순서
> - 예방 점검 주기(초안: 출시 전 1회와 이후 분기 1회)

## 영수증 이미지

영수증 인식은 아직 구현하지 않았다. 원본 이미지를 서버나 스토리지에 저장하지 않는 것이 확정 정책이며, 구현은 이를 따른다.

> 구현 제안
>
> - 서버는 받은 이미지를 요청 처리 중 메모리에서만 쓰고 파일이나 Object Storage에 쓰지 않는다. 웹 서버 로그는 요청 본문을 남기지 않는다.
> - 앱은 기기 내장 OCR(iOS Vision, Android ML Kit)로 카드번호, 승인번호, 전화번호 같은 민감 정보를 먼저 가린 뒤 서버로 보낸다. 서버는 추출 결과에서도 이 항목을 빼고 반환한다.
> - 기기 내장 OCR의 가리기 정확도는 Android가 iOS보다 낮다(공개 영수증 23장 시험에서 iOS 35/37, Android 30/37). Android는 보내기 전에 사용자가 가린 결과를 확인하고 더 가릴 수 있어야 한다.

> 논의 필요
>
> 인식 엔진(해외 AI, 국내 리전 OCR 등)을 정하면 위탁과 국외 이전 대상, 엔진 쪽 요청 데이터 보관 기간을 이 절에 추가한다.
